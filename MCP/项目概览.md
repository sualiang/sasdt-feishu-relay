# 项目概览 — 飞书中转服务

> **维护人**：技术总监（小克） | **最后更新**：2026-07-26

---

## 背景

SASDT 体系 5 个角色分布在不同的 AI 平台上，需要一个统一的消息中枢来接收飞书 Bot 事件并转发给对应角色处理。

## 核心功能

1. **Webhook 接收** — 接收飞书事件推送（消息、@机器人、群聊等）
2. **角色路由** — 按路径 `/webhook/:role` 分发给 5 个角色
3. **AI 适配器** — 将消息转发给各角色的 AI 平台（DeepSeek/豆包/Claude/千问）
4. **上下文管理** — 维护每个角色的对话上下文和历史
5. **日志审计** — 全量操作日志，小千可审计

## 5 个 Webhook 端点

| 端点 | 角色 | AI 平台 | 处理内容 |
|------|------|---------|---------|
| `/webhook/doubao` | 豆包 | 豆包 API | 项目/测试相关 |
| `/webhook/ke` | 小克 | DeepSeek | 架构/技术相关 |
| `/webhook/kai` | 小开 | Claude API | 开发任务相关 |
| `/webhook/long` | 小龙 | OpenClaw | 运维/部署相关 |
| `/webhook/qian` | 小千 | 千问 API | 审计相关 |

## 外部依赖

| 依赖 | 用途 |
|------|------|
| 飞书开放平台 | 事件订阅、API 调用 |
| 各 AI 平台 API | 消息处理 |
| MySQL（可选） | 持久化上下文和日志 |
| Redis（可选） | 会话缓存 |
