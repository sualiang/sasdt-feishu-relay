## 三、飞书 Webhook 接入（最核心）

### 3.1 事件订阅配置

飞书开放平台侧：
- 事件：`im.message.receive_v1`（接收消息）
- 请求地址：`https://你的域名/webhook/event`
- 回调验证：飞书 GET 请求带 `challenge` 参数，原样返回

### 3.2 签名校验

飞书每个 POST 请求头携带：
- `X-Lark-Request-Timestamp` — 时间戳
- `X-Lark-Request-Nonce` — 随机数
- `X-Lark-Signature` — 签名

校验算法（务必实现）：

```typescript
function verifySignature(
  timestamp: string,
  nonce: string,
  body: string,
  appSecret: string
): boolean {
  const signStr = timestamp + nonce + appSecret + body;
  const signature = crypto.createHash('sha256').update(signStr).digest('hex');
  // 比较 signature 和请求头的 X-Lark-Signature
}
```

### 3.3 消息解析

飞书消息事件 Payload 结构：

```typescript
interface FeishuEvent {
  schema: string;
  header: {
    event_id: string;
    token: string;
    create_time: string;
    event_type: string;
    app_id: string;
  };
  event: {
    sender: {
      sender_id: { union_id: string; user_id: string; open_id: string };
      sender_type: 'user' | 'bot';
      tenant_key: string;
    };
    message: {
      message_id: string;
      root_id: string;
      parent_id: string;
      create_time: string;
      chat_id: string;
      chat_type: 'group' | 'p2p';
      message_type: 'text' | 'image' | 'post' | 'file';
      content: string;  // JSON 字符串，text 时格式: {"text":"消息内容"}
    };
  };
}
```

群聊 @ 机器人时，消息文本会包含 `@机器人名`，**需要先清洗掉**再交给 AI 处理。

## 四、角色路由逻辑

### 4.1 路由规则

```
收到飞书消息
    │
    ├── 私聊（chat_type === 'p2p'）
    │   └── 直接路由到 Bot 对应的角色
    │
    └── 群聊 @（chat_type === 'group' 且消息含 @机器人）
        ├── 按 Webhook 路径路由（/webhook/xxx）
        └── 如果没有匹配路径 → 默认回复「未识别的机器人」
```

### 4.2 每个角色的回复逻辑

| 角色 | 收到消息后 |
|------|-----------|
| 豆包 | 调用豆包 API 处理 → 回复飞书群 |
| 小克 | 暂不做 AI 处理，回复「小克（技术总监）已收到，处理后回复」 |
| 小开 | 调用 DeepSeek/Claude API 处理 → 回复飞书群 |
| 小龙 | 调用 OpenClaw → 回复飞书群 |
| 小千 | 调用千问 API 处理 → 回复飞书群 |

小克特殊说明：我目前在 Cowork 沙箱，无法实时收消息。所以 `/webhook/ke` 暂时只回复固定文案。等我这边飞书通道打通后，消息直接在当前会话处理。

### 4.3 消息回复

通过飞书 API 发送消息：

```typescript
// POST https://open.feishu.cn/open-apis/im/v1/messages
// 需要 access_token（通过 app_id + app_secret 获取）
{
  "receive_id": "chat_id",
  "msg_type": "text",
  "content": "{\"text\":\"回复内容\"}"
}
```

## 五、AI 适配器接口

所有 AI 适配器实现统一接口：

```typescript
interface AIAdapter {
  name: string;
  process(message: string, context?: MessageContext): Promise<AIResponse>;
}

interface AIResponse {
  text: string;
  raw?: any;  // 原始响应，用于审计
}

interface MessageContext {
  sessionId: string;
  history: MessageHistory[];
}
```

4 个适配器：

| 适配器 | API 地址 | 认证方式 |
|--------|---------|---------|
| `deepseek.ts` | `https://api.deepseek.com/chat/completions` | API Key Header |
| `doubao.ts` | 使用豆包桌面客户端 API | 待定（可先用 webhook 回调） |
| `claude.ts` | `https://api.anthropic.com/v1/messages` | API Key Header |
| `qianwen.ts` | 千问 API | API Key Header |

**适配器必须在 `adapters/types.ts` 中定义接口，各适配器实现该接口。** 未来新增角色只需加新的适配器文件，不改现有代码。

所有配置通过 `config/env.ts` 统一读取和校验，**禁止**在业务代码中直接 `process.env`。必须配置的变量缺失时，启动时报错退出。

## 七、日志规范

| 日志级别 | 使用场景 | 输出内容 |
|---------|---------|---------|
| error | 系统错误、API 调用失败 | 错误堆栈、请求参数 |
| warn | 异常但不影响运行 | 飞书签名校验失败 |

## 八、错误处理

全局错误处理中间件捕获所有未处理异常：

```typescript
app.use((err, req, res, next) => {
  logger.error('未捕获错误', err);
  res.status(500).json({ code: 500, message: '内部错误' });
});
```

对外部 API 调用（飞书 API、AI API）必须实现：
- 超时控制（默认 30 秒）
- 重试机制（最多 3 次，指数退避）
- 熔断保护（连续 5 次失败后暂停调用 60 秒）
